Príkazy na serveri

Kto: správca servera (root).
Kedy: pri inštalácii, výmene kľúča, v núdzi (strata telefónu, zamknutá ochrana, nefunkční správcovia).
Závisí od: aktivované virtuálne prostredie NetBoxu. Núdzové príkazy sa zapisujú do auditu.

Spúšťajú sa takto (nahraď <príkaz>):

sudo bash -c 'source /opt/netbox/venv/bin/activate && cd /opt/netbox/netbox && python manage.py <príkaz>'
PríkazČo robí
userpin_generate_key [--key-id k1]vygeneruje náhodný šifrovací kľúč (vypíše ho, nič neukladá)
userpin_rotate_keyprešifruje všetko pod aktívnym kľúčom (PIN hashe, 2FA, záložné kódy, SMTP heslo); v jednej transakcii, pri chybe sa nič nezmení
userpin_checkoverí, že sa všetko uložené pod kľúčmi dá dešifrovať, a ukáže, koľko hodnôt a osôb len s PIN-om čaká na starý kľúč
userpin_keeper [--add meno]zobrazí strážcov alebo vymenuje jedného (audit, e-mail všetkým strážcom a superuserom)
userpin_default_deny [--on | --off]zobrazí alebo prepne globálnu ochranu (audit, e-mail; zapnutie potrebuje strážcu)
userpin_area_owners <oblasť> [--set mená…] [--force]zobrazí alebo nahradí správcov oblasti (audit); bez --force odmietne ľudí, ktorí by správcami byť nemohli
userpin_reset_2fa <používateľ>núdzovo odstráni 2FA (napr. master bez telefónu a záložných kódov; audit)
userpin_access_test <používateľ> [--url …] [--all] [--writes]ukáže, čo používateľ dostane zo stránok, REST API (prehliadač) a zoznamov (test ochrany). --url pridá ďalšiu adresu, --all skúsi každú stránku NetBoxu, --writes aj pridanie, zmenu a zmazanie

Kontrola: pin_check.sh

Kto: správca; skript sa dá spustiť aj z iného počítača než server.
Kedy: po inštalácii, po aktualizácii pluginu aj NetBoxu.
Závisí od: curl; pri voľbe --server root na serveri NetBoxu.

Skript tools/pin_check.sh (v repozitári) kontroluje všetko, čo sa dá zvonku, a so --server aj na serveri. Nikdy neukladá ani nevypisuje PIN či token (PIN sa pýta potichu). Výsledok je počet OK / FAIL / WARN.

bash pin_check.sh http://172.30.1.25                                  # len anonymné kontroly
bash pin_check.sh http://172.30.1.25 --pin /pin/                      # + prihlási osobu len s PIN-om
NB_TOKEN=xxxx bash pin_check.sh http://172.30.1.25                    # + kontroly s API tokenom
sudo bash pin_check.sh http://127.0.0.1 --pin /pin/ --server          # + migrácie, služby, kľúče, strážcovia

Voľby: --pin <cesta> (adresa stránky PIN-only, predvolene /pin/), --wrong (skúsi jeden zlý PIN; počíta sa ako chybný pokus), --write (skúsi pridať tenanta ako osoba len s PIN-om a zmaže ho), --server (vyžaduje root). Premenné: NB_TOKEN, NB_VENV, NB_DIR, LIST.

Kontroly majú oddiely: 0 dostupnosť; 1 nikto neprihlásený; 2 s API tokenom; 3 osoba len s PIN-om; 4 čo osoba nikdy nesmie dosiahnuť; 5 stránka, ktorú smie otvoriť; 6 pridanie ako osoba len s PIN-om; 7 odhlásenie; 8 na serveri (migrácie, služby, kľúče, strážcovia). Známe neškodné upozornenia: /static/docs/ servíruje nginx (zatvorí sa location /static/docs/ { return 404; }) a LOGIN_REQUIRED nie je True (nastav v configuration.py; NetBox 5.0 ho zruší).

Bezpečnostný model

PIN ──Argon2id + soľ──► hash ──AES-256-GCM (kľúč z konfigurácie, viazaný na ID používateľa)──► databáza
  • Samotný výpis databázy neobsahuje nič použiteľné, ani čo by sa dalo lámať offline.
  • Šifrovaný text je viazaný na používateľa: hash skopírovaný do riadku iného používateľa sa nedešifruje.
  • Zlé pokusy sa počítajú pod zámkom riadku, takže paralelné hádanie zablokovanie neobíde.
  • Zmena alebo reset PINu zneplatní všetky odomknutia. Tajomstvá TOTP sú šifrované rovnako; kód TOTP sa prijme len raz.
  • Záložné kódy (100 bitov) a e-mailové kódy sa ukladajú len ako odtlačky, jednorazové a krátko platné.
  • Obnova nikdy neobíde 2FA. PIN je len autentifikačný faktor („som to naozaj ja pri tomto počítači“), nepoužíva sa ako kľúč na šifrovanie iných dát.
  • Požiadavky s API tokenom plugin PIN-om neposudzuje (token nesie oprávnenia NetBoxu): preto sú vlastné tokeny predvolene zakázané a pri výnimkách sa povoľujú po jednom.
  • Prístup na server riadi firewall; samostatný port alebo hostname pre prihlásenie osôb len s PIN-om plugin nevynucuje, ak treba, rieši sa v nginxe a firewalle.
  • Kto má root alebo prístup do databázy na serveri, obíde akýkoľvek plugin: odpoveďou je audit.

Použitie z iného pluginu

Kto: vývojár pluginu pre NetBox.
Kedy: keď chce iný plugin chrániť citlivé stránky PINom.
Závisí od: netbox-user-pin ako závislosť pluginu; verzia API (service.API_VERSION = 2, areas.API_VERSION = 1; API len rastie).
from netbox_user_pin.mixins import PinRequiredMixin, StepUpRequiredMixin, pin_required, step_up_required

class ProjectView(PinRequiredMixin, generic.ObjectView):
    pin_scope = 'projects'          # pri režime rozsahu „osobitné podľa rozsahu“

class ProjectDeleteView(StepUpRequiredMixin, generic.ObjectDeleteView):
    ...                             # citlivá akcia: čerstvé PIN + 2FA

@pin_required(scope='projects')
def download(request, pk): ...

Používateľ je presmerovaný na nastaviť PIN, zmeniť PIN (vypršal) alebo zadať PIN a potom späť. Požiadavky HTMX dostanú hlavičku HX-Redirect.

Servisné API netbox_user_pin.service: has_pin(user), is_unlocked(request, scope), unlock(request, pin, scope), verify_pin(user, pin), lock(request), has_step_up(request), has_2fa(user), is_allowed(user). Signály (netbox_user_pin.signals, sender=UserPin): pin_set, pin_changed, pin_reset, pin_unlocked, pin_failed, pin_locked_out, pin_locked.

Oblasť pluginu

from netbox_user_pin import areas

# v ready(): oblasť je aktívna, kým je zapnutý vlastný prepínač „PIN integrácia“ pluginu
areas.register('netbox_libreoxi', 'LibreOXI', targets=['netbox_libreoxi'],
               rights={'config': 'Zobraziť konfigurácie zariadení'},
               profiles=[('Len logy', ['view']), ('Konfigurácie', ['view', 'config'])],
               enabled=lambda: LibreOXISettings.objects.first().pin_integration)

# vo view, pre jemnejšie práva
if (response := areas.require(request, 'netbox_libreoxi', 'config')) is not None:
    return response            # stránka „bez prístupu – požiadaj o ňu“
areas.can(request.user, 'netbox_libreoxi', 'config')   # True / False

Zmeny

Verzia v kóde je 2.0.0 (vydanie na GitHube) a 2.0.1 (vetva feature/exception-allowlist). Pôvodný základ bol 0.38.4 (commit 7bed7de); priebežné čísla 2.0.1 až 2.2.2 v histórii commitov boli pracovné označenia, všetko patrí do línie 2.0.0 a je rozdelené podľa tém.

2.0.1: oprávnenia výnimiek

  • Výnimka už nie je „všetko alebo nič“: strážca zaškrtáva, čo smie používateľ používať (heslo predvolene povolené; profil, predvoľby, záložky, notifikácie, odbery, API tokeny a API s tokenom na povolenie).
  • Čo nie je povolené, je skryté z menu a kariet a zakázané priamou adresou (403); token bez povoleného API je odmietnutý. Strážca je bez obmedzení.
  • Odkaz „Zmeniť heslo“ v menu používateľa; zvonček sa skryje, ak nie sú povolené notifikácie.
  • Šípka ▾ pod menom používateľa so zaškrtávacími poľami a zelenými/červenými štítkami; existujúci používateľ sa neponúka znova a opätovné pridanie nič neprepíše.
  • Nové pole PolicyException.allowed (migrácia 0042); slovenský preklad.
  • Prepínač výnimky (Výnimka zapnutá / vypnutá) pri každom používateľovi: vypnutá výnimka nechá používateľa riadiť PIN-om bez odobratia riadku; zapnutá ho nechá riadiť NetBoxom.
  • Úprava konca výnimky (dátum a čas, prázdne = bez konca); po uplynutí sa prepínač sám prepne na vypnutá (systémová úloha, audit, e-mail strážcom); ukončenú výnimku treba pred zapnutím predĺžiť.
  • Hľadanie a stránkovanie zoznamu výnimiek (meno, účet, dôvod; filter stavu; po 25) a vyhľadávacie pole pri pridávaní používateľa.
  • Nové pole PolicyException.active (migrácia 0043).
  • Pomocné polia formulárov (Owner group, Tenant group, Contact group, výbery lokality pri kábloch, rack a pod.) sa skrývajú a zamykajú spolu s poľom, ku ktorému patria; plugin ich nájde sám zo väzieb výberov (overené na všetkých 221 formulároch NetBoxu 4.7.2).
  • E-maily a audit zmien v chránených oblastiach: zmena objektu používateľom v skupine sa zapíše do Audit logu a strážcovia a správca úseku dostanú e-mail (súhrn alebo pri každej zmene). Nové polia v nastaveniach (migrácia 0044).
  • Osobné číslo + PIN pre osoby len s PIN-om: osobné číslo je povinné, jedinečné a nemenné; osoba sa volá UserPIN : OC všade; prihlásenie číslom a PIN-om, PIN nemusí byť jedinečný; globálne pravidlá (povinné číslo, najkratší PIN, písmeno, číslica) s e-mailom a vynútenou zmenou PINu; červený oznam na prihlasovacej stránke. Migrácia 0046.
  • Audit zmien objektov aj pre osoby len s PIN-om, s rozbaliteľným detailom zmenených polí (hodnoty tajných polí skryté).
  • Osoba len s PIN-om vidí len oblasti svojich skupín (vždy režim B).

Kľúče a bezpečnosť

  • Rotácia kľúča pokrýva aj 2FA, záložné kódy, SMTP heslo a index osôb len s PIN-om; userpin_check overí všetky šifrované hodnoty.
  • Odstránenie PINu používateľa bez 2FA; userpin_area_owners kontroluje oprávnenosť.
  • Master spravuje PINy, kým nie je zástupca CORE, aj pri existujúcich strážcoch.

Nový model ochrany

  • PIN riadi iba osoby len s PIN-om a používateľov v skupine alebo správcov úsekov; ostatní pracujú podľa oprávnení NetBoxu (menu a API kľúče vrátane).
  • Osoby len s PIN-om nie sú používatelia NetBoxu (skryté v zoznamoch), nemajú žiadosti a bez skupiny môžu len zmeniť PIN.
  • Ochrana ZAP riadi všetkých okrem strážcov a výnimiek; VYP necháva NetBox a pozastaví osoby len s PIN-om. Prepínač ZAP/VYP je v rozhraní (len strážcovia) a ukazuje skutočný stav. Výnimka vs. skupina: skupina čaká pod výnimkou.
  • Strážcovia ochrany: pravidlo posledného strážcu, núdzové príkazy (userpin_keeper, userpin_default_deny).

Správcovia úsekov a žiadosti

  • Správca úseku s plnou mocou nad svojím úsekom (strážcovia nad ním); osoby len s PIN-om pod správcom; žiadosti správcovi aj strážcom s e-mailami o rozhodnutiach.
  • Vymenúva len strážca; uvoľnená oprávnenosť (PIN + 2FA, bez roly oddelenia).

Osoby len s PIN-om

  • E-maily oboma smermi: osoba o zmenách správcu; správcovia zhrnutie každých N minút alebo pri každej zmene (nie oboje), predmet PinUserNNNN vykonal zmenu, telo: čas, objekt, zmenené polia (z → na); odosielanie po uložení cez netbox-rq.
  • Rozbaľovacie zoznamy vo formulároch fungujú; ukladanie vlastných stĺpcov tabuliek.
  • Podmienky pre polia typu relácia: obsahuje / začína na / je jedno z, viac hodnôt, tlačidlo Podmienky.

Pracovný čas

  • Všeobecné a vlastné pravidlá, krajina so štátnymi sviatkami (knižnica holidays), pracovné dni a hodiny; vždy zobrazený pracovný čas.
  • Mimo času len čítanie; po konci 30 minút a jedno uloženie; krajina v jazyku osoby, dni Po–Pi.

Nástroje

  • tools/pin_check.sh: kontrola zvonku aj na serveri; závislosť holidays v pyproject.toml; slovenské preklady; príprava local_requirements.txt pre upgrade NetBoxu v rámci 4.7.x.

Čo plugin zatiaľ nerobí

  • Dovolenky a vlastné firemné voľné dni v pracovnom čase.
  • API pre bežných používateľov v skupine je stále riadené právami skupiny (nie je úplne uzavreté).
  • Samostatný port alebo hostname pre prihlásenie osôb len s PIN-om (rieši sa v nginxe a firewalle).
