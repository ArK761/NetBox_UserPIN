O pluguine

User PIN je plugin pre NetBox 4.7+ (Python 3.12+). Dáva každému používateľovi osobný PIN a nad ním stavia ochranu citlivých častí NetBoxu: chránené oblasti, skupiny s právami, pravidlá polí, prístupy len cez PIN pre ľudí bez účtu v NetBoxe, pracovný čas a podrobný audit.

  • Jeden PIN na používateľa, platí pre všetky pluginy, ktoré User PIN používajú.
  • PIN je uložený ako hash Argon2id zašifrovaný AES-256-GCM. Kľúč je len v konfigurácii NetBoxu, nie v databáze.
  • Dvojfaktorové overenie (2FA, TOTP: Microsoft / Google Authenticator …) so záložnými kódmi.
  • Odomknutie na nastavený čas, zablokovanie po viacerých zlých pokusoch, odmietnutie slabých PINov.
  • Roly CORE a oddelenia (pozvánky, zastupovanie, presuny), schvaľovanie „štyri oči“.
  • Chránené oblasti: objekty NetBoxu (aplikácia alebo typ objektu) vidí len ten, kto má prístup z oblasti, aj superuser.
  • Globálna ochrana „zakázať všetko, čo nie je povolené“ so zapínaním a vypínaním, strážcovia ochrany, správcovia úsekov a výnimky.
  • Prístupy len cez PIN (PIN-only) pre ľudí bez účtu, s pracovným časom a štátnymi sviatkami.
  • E-maily oboma smermi, audit všetkého, kontrolný skript a núdzové príkazy na serveri.
  • Jazyky: angličtina a slovenčina (Nastavenia → Všeobecné) pre stránky pluginu aj e-maily.
Pomenovanie v menu. V rozhraní sa používa: Môj PIN, Chránené oblasti, Prístup len cez PIN › Ľudia len s PIN-om, Oddelenia, Schvaľovania, Audit log, Nastavenia, Mail. Správca úseku sa v angličtine volá „section manager“, strážca ochrany „protection keeper“.

Kto je kto

KtoČo ho riadiČo môže
Prístup len cez PIN (PinUserNNNN)iba jeho skupiny (vždy)žiadne API, žiadne žiadosti. Bez skupiny môže len zmeniť svoj PIN. Nie je používateľ NetBoxu (skrytý vo všetkých zoznamoch).
Bežný používateľ v skupine (ochrana zapnutá)iba to, čo povoľujú jeho skupinynezadáva PIN, nemá API kľúč.
Bežný používateľ s výnimkousamotné oprávnenia NetBoxu; z účtových stránok a API iba to, čo strážca povolil (predvolene heslo)stránky pluginu podľa jeho role.
Správca úsekuNetBox ako každý používateľ; plná moc nad svojím úsekomskupiny, polia, členovia a žiadosti svojho úseku (typ objektu alebo celá oblasť); zakladá a spravuje prístupy len cez PIN, ktoré sú pod ním.
Strážca ochranyvšetkooblasti, typy objektov, správcovia úsekov, výnimky, prepínač ZAP/VYP, všetky prístupy len cez PIN; presúva prístup pod správcu.
Master (superuser)NetBoxpozýva zástupcov CORE; kým nie je žiadny strážca, spravuje všetko; kým nie je zástupca CORE, spravuje PINy.
Zástupca CORE—všetko okrem CORE; zakladá oddelenia a vymenúva vedúcich.
Vedúci oddelenia / delegát—PINy členov svojho oddelenia; vedúci pozýva delegátov (min. 2 na oddelenie).

Strážcom môže byť len človek s PINom a 2FA. Správca úseku nemusí mať rolu oddelenia, ale potrebuje PIN a 2FA.

Inštalácia

Požiadavky

NetBox 4.7.x, Python 3.12+. Závislosti pluginu: argon2-cffi, cryptography, segno, holidays (štátne sviatky; funguje offline).

Postup

source /opt/netbox/venv/bin/activate
pip install "argon2-cffi>=23.1" "cryptography>=42" "segno>=1.5" "holidays>=0.50"
pip install --upgrade --force-reinstall --no-deps "git+https://github.com/ArK761/NetBox_UserPIN.git@2.0.0"
Pozor na --no-deps. Táto voľba neinštaluje závislosti. Na serveri, kde plugin ešte nebol, ich nainštaluj samostatne (prvý riadok). Inak NetBox hlási ModuleNotFoundError: No module named 'argon2'.

Vygeneruj šifrovací kľúč (plugin ešte nebeží, použi obyčajný Python):

python3 -c "import base64,os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
# alebo ľubovoľne dlhý náhodný text (min. 32 znakov):
openssl rand -base64 64 | tr -d '\n'

Dlhší kľúč nie je silnejší: šifrovanie vždy používa 256 bitov. Dôležité je, aby bol náhodný. Po spustení pluginu robí to isté python manage.py userpin_generate_key [--key-id k1] (nič neukladá, len vypíše).

Do /opt/netbox/netbox/netbox/configuration.py:

PLUGINS = ['netbox_user_pin']

PLUGINS_CONFIG = {
    'netbox_user_pin': {
        'encryption_keys': {'k1': '<vygenerovaný kľúč>'},
        'active_key_id': 'k1',
    },
}
Kľúč si zálohuj offline a nikdy ho nedávaj do tej istej zálohy ako databázu. Ak sa stratí, dáta NetBoxu ostanú, ale všetko, čo plugin uložil pod kľúčom, je preč: PINy, 2FA, záložné kódy, SMTP heslo a prihlasovanie ľudí len s PIN-om. Všetci si ich nastavia znova.

Migrácie a reštart:

cd /opt/netbox/netbox
python manage.py migrate netbox_user_pin
sudo systemctl restart netbox netbox-rq

Prvé spustenie

  1. Prihlás sa ako superuser → User PIN → Môj PIN → nastav PIN a 2FA (potrebné pre každú administratívnu akciu).
  2. V Nastaveniach a na stránke Mail nastav povolené e-mailové domény a SMTP (pozri ďalej).
  3. Na stránke Používatelia povoľ používanie PINu tým, ktorí ho majú mať.
  4. V Chránených oblastiach vymenuj prvého strážcu ochrany (zapne globálnu ochranu).

Jednoriadková aktualizácia pluginu

sudo bash -c 'source /opt/netbox/venv/bin/activate && pip install --upgrade holidays && pip install --upgrade --force-reinstall --no-deps "git+https://github.com/ArK761/NetBox_UserPIN.git@<tag-alebo-commit>" && cd /opt/netbox/netbox && python manage.py migrate netbox_user_pin && systemctl restart netbox netbox-rq'
Produkcia: pred každou migráciou urob zálohu databázy, napríklad sudo -u postgres pg_dump netbox | gzip > /root/netbox-$(date +%F-%H%M).sql.gz. Kľúče v configuration.py pritom nemeň.

  • Kód niektorých pluginov býva na inej vetve než main. Vtedy ponechaj pripnutý commit, kým vetvu nezlúčiš.
  • Upgraduj len v rámci 4.7.x: ostatné pluginy majú obmedzenie 4.7.0–4.7.99.
  • Po upgrade skontroluj verziu pluginov (odznak User PIN vX · commit) a spusti kontrolný skript (pozri kapitolu Kontrola).

Môj PIN, 2FA a odomknutie

PIN

  • Nastavenie: Môj PIN → nastav PIN (predvolene 6 číslic; slabé PINy ako 111111, 123456, 121212 a vlastný zoznam sa odmietnu).
  • Odomknutie: chránená stránka vyžiada PIN („zadaj PIN a pokračuj“). Odomknutie trvá nastavený čas (predvolene 15 minút), môže sa predlžovať pri aktivite a platí buď pre všetko, alebo po oblastiach.
  • Zablokovanie: po 5 zlých pokusoch na 30 minút. Zlé PINy a zlé kódy 2FA sa počítajú zvlášť; limit dosiahnutý ktorýmkoľvek zablokuje.
  • Rotácia: predvolene po 180 dňoch s upozornením 14 dní vopred, vynútenou zmenou a tlačidlom na skúšku rotácie.
  • Zmena PINu alebo reset zruší všetky existujúce odomknutia používateľa.

Dvojfaktorové overenie (2FA)

Môj PIN → 2FA: naskenuj QR kód aplikáciou (Microsoft / Google Authenticator …) a potvrď kódom. Kód TOTP sa prijme len raz (ochrana proti zopakovaniu). 2FA je potrebné pre každú administratívnu akciu, pre strážcov, správcov úsekov a delegátov.

Záložné kódy

Môj PIN → Zobraziť záložné kódy: po overení PIN + kód 2FA, alebo (bez telefónu) PIN + overovací kód z e-mailu. Kódy sa ukážu len v prehliadači (použité sú preškrtnuté) a dajú sa vygenerovať nové. Používateľ dostane e-mailové upozornenie. Samotné kódy sa nikdy neposielajú e-mailom.

Potvrdenie administratívnych akcií (step-up)

Administratívna akcia vyžaduje čerstvé potvrdenie PIN + 2FA (platí niekoľko minút, predvolene 5). Potvrdzuje sa v okne priamo na stránke a akcia pokračuje bez opustenia stránky. Každodenné akcie (povoliť/zakázať PIN, zrušiť zablokovanie, vynútiť zmenu PINu, presuny medzi oddeleniami) vyžadujú len PIN; resety, pozastavenie, roly a zrušenie oddelenia vyžadujú PIN + 2FA. Voľba Vyžadovať 2FA aj pre nastavenia to rozšíri aj na akcie len s PINom. Pri správe oblastí sa 2FA pýta len raz za nastavený čas (predvolene 8 hodín).

Zabudnutý PIN (samoobsluha)

  1. Môj PIN → Zabudnutý PIN (alebo odkaz na stránke odomknutia) → Odoslať kód: 8-miestny kód príde e-mailom (len do povolenej domény, platí 15 minút, max. 5 pokusov, opätovné odoslanie po 60 s).
  2. Zadaj kód z e-mailu a kód 2FA (alebo záložný kód) a nový PIN.

Bez e-mailu v povolenej doméne alebo bez 2FA sa obnova neponúka: PIN resetuje správca.

Núdzový reset 2FA na serveri

sudo bash -c 'source /opt/netbox/venv/bin/activate && cd /opt/netbox/netbox && python manage.py userpin_reset_2fa <používateľ>'

Zobrazuje sa pri každom účte (Používatelia → Akcie → Núdzovo: príkaz na serveri) aj v Môj PIN. Cesty sa berú z nastavení cli_venv a cli_netbox_dir.

Mail

E-maily (kódy obnovy, upozornenia) idú cez SMTP server nastavený na stránke Mail: názov odosielateľa (predvolene NetBox PIN), server, port (predvolene 25), šifrovanie (vypnuté / STARTTLS / SSL), automatické TLS, SMTP autentifikácia so servisným účtom (heslo je zašifrované a nikdy sa nezobrazuje) a test spojenia. Ak tam server nie je, použije sa EMAIL z NetBoxu.

  • Povolené domény sa zapisujú ako @firma.sk, zhoda presná (bez poddomén a podobných mien). Overenie: adresa → kód e-mailom → zadať kód. Overiť znova kedykoľvek.
  • E-mail pred overením domény nikam neodíde. Pozvánky smie dostať len používateľ s e-mailom v overenej doméne.
  • Upozornenia o bezpečnosti (zmena, reset, zablokovanie, blížiaca sa expirácia) sa dajú zapnúť/vypnúť; test e-mail sa pošle vybranému používateľovi (výber ukáže účet, meno aj adresu).

Kým používateľ nepotvrdí, starý PIN funguje; správca môže reset zrušiť. Používateľ bez 2FA nič nepotvrdí: správca použije Odstrániť PIN (PIN + 2FA správcu) a používateľ si pri najbližšej výzve nastaví nový.

Schvaľovanie „štyri oči“

Nastavenia → Schvaľovanie štyri oči (potrebuje aspoň dvoch aktívnych zástupcov CORE s PINom a 2FA). Vyber, na čo sa vzťahuje: roly, nastavenia (vrátane mailu), prístup PIN. Zmena potom vytvorí žiadosť: žiadateľ potvrdí PIN + 2FA (a dôvod), druhá oprávnená osoba dostane upozornenie (zvonček) a e-mail, v Schvaľovaniach potvrdí alebo zamietne vlastným PIN + 2FA. Stránka žiadosti sa obnovuje a obaja vidia potvrdenia (čas, IP). Po druhom potvrdení sa zmena vykoná. Žiadosti expirujú (predvolene 24 h). Break-glass (predvolene vypnuté): superuser smie žiadosť vykonať sám s dôvodom; všetci správcovia sa dozvedia a v audite je označená. Štyri oči sa nedajú vypnúť, kým existuje oddelenie; vypnutie vyžaduje dvoch ľudí a ukončí delegovanie CORE.

Chránené oblasti

Oblasť chráni objekty jednej alebo viacerých aplikácií (dcim, ipam, netbox_libreoxi …) alebo typy objektov (users.user, dcim.device …), vybrané zo zoznamu. V oblasti nikto nie je boh: rolu a oprávnenia používateľa v NetBoxe plugin vôbec nezohľadňuje, rozhoduje prístup (skupina), ktorý udelia správcovia úsekov alebo strážcovia, vrátane mastera. Dvere (položka menu, karta) vidí každý; kto nemá kľúč, je pri vstupe odmietnutý a dozvie sa, kto prístup spravuje.

Skupiny (spôsob, ako sa dáva prístup)

Pri chránenom type objektu (napr. DCIM › Device) správca vytvorí skupiny: pomenovaná sada práv (napr. Čítanie, Zapisovanie) s kartami a poľami, a pridá do nich ľudí.

  • Práva: zobraziť, pridať, zmeniť, zmazať, plus práva, ktoré definuje plugin. Zápisové práva so sebou nesú čítanie.
  • Import a export sú samostatné práva (Smie importovať, Smie exportovať), predvolene vypnuté. Bez nich sa tlačidlá Import/Export nevykreslia a stránky odpovedia „bez prístupu“. Import vyžaduje aj pridať.
  • Záznamy: skupina môže platiť len pre riadky podľa podmienky (napr. názov obsahuje agg) alebo pre všetky.
  • Používateľ je v jednej skupine na typ: pridanie do inej ho presunie; odchod z poslednej znamená žiadny prístup. Prístup môže mať čas alebo byť bez limitu.
  • Viac oblastí sa sčítava (zjednotenie): kto nič nedostal, nemá nič.

Pravidlá polí

Pre skupinu a typ objektu je každé pole skryté, len na čítanie alebo čítanie a zápis. Pole prepojené na iné objekty sa dá obmedziť na hodnoty podľa podmienky: obsahuje (~), začína na (^), je jedno z (=, existujúce hodnoty); viac hodnôt ako štítky; podmienky sa rozbaľujú tlačidlom Podmienky. Pravidlo bez skupiny skryje pole pred všetkými v oblasti. Skryté vlastné pole si ponechá uložené dáta (uloženie objektu ich nikdy nezmaže).

Karty detailu

Karta zostáva v lište (dvere vidno), čo otvorí, sa rozhodne takto: systémová karta NetBoxu sa otvorí len ak je pre používateľa zaškrtnutá v Polia → Karty detailu (nový prístup povoľuje len hlavnú stránku); karta, ktorá vypisuje iné objekty (rozhrania zariadenia), potrebuje právo aj na ich typ; karta pluginu sa riadi chránenou oblasťou tohto pluginu.

Žiadosti o prístup

Na stránke „bez prístupu“ používateľ zaškrtne potrebné práva (zobraziť / pridať / zmeniť / zmazať), napíše dôvod a odošle. E-mail s odkazom dostanú správca úseku aj strážcovia. Odkaz otvorí stránku s tým, kto žiada o čo a prečo; rozhodujúci môže zmeniť práva a trvanie a potvrdí OK. Ak pre typ objektu oblasť ešte neexistuje, OK ju vytvorí a používateľa pridá. Nikto nerozhoduje o vlastnej žiadosti. Každé rozhodnutie sa pošle e-mailom žiadateľovi, strážcom a správcovi. Žiadosti sa dajú vypnúť (Používatelia smú žiadať o prístup). Bez PINu je používateľ pri vstupe poslaný vytvoriť si ho (bez 2FA).

Oblasť registrovaná pluginom

Plugin si môže zaregistrovať oblasť (areas.register(...)); je chránený, keď je zapnutý jeho vlastný prepínač „PIN integrácia“. Prvé nastavenie je neutrálne: kým oblasť nemá správcov, prístup majú len strážcovia (bez strážcu superuseri), aby sa nikto nezamkol. Citlivé aplikácie (users, auth, core …) môže do oblasti vložiť len strážca.

Globálna ochrana (ZAP / VYP)

Na stránke Chránené oblasti v hornej karte Ochrana (len strážcovia).

  • ZAP: čo žiadna skupina nepovoľuje, je zakázané všetkým okrem strážcov a výnimiek. Prístupy len cez PIN vidia iba svoje skupiny. Zakázané sa týka každej cesty: zoznamy, detaily, REST API, GraphQL, vyhľadávanie, widgety, menu a tlačidlá (superuser, ktorý nie je strážca, nevidí Používateľov, Skupiny, Oprávnenia, Úlohy, Pozadie …). Vlastný profil, záložky, notifikácie a predvoľby ostávajú otvorené, ale len vlastné.
  • VYP: všetci pracujú len podľa oprávnení NetBoxu; prístupy len cez PIN môžu iba zmeniť svoj PIN a dozvedia sa, že funkciu vypol správca.
  • Prvého strážcu vymenuje master; jeho vymenovanie ochranu zapne. Strážca potrebuje PIN a 2FA, nemôže si vypnúť 2FA ani odísť sám (musí ho prevziať iný), posledného strážcu nemožno odobrať. Ak sa účet posledného strážcu zmaže, ochrana sa vypne a nedá sa zapnúť, kým strážca nie je.
  • Čo sa nepovolené zobrazuje: A – dvere (menu vidno, otvorenie hlási „bez prístupu“ a ponúkne žiadosť) alebo B – nič (používateľ nevidí nič, len heslo a stránky pluginu).
  • Používatelia smú žiadať o prístup (predvolene zapnuté) a smú vytvoriť vlastný API kľúč (predvolene vypnuté: kľúč pracuje s oprávneniami NetBoxu a PIN ho neposudzuje, preto zapínaj len pri užších oprávneniach).
  • Na koho sa ochrana vzťahuje: Len ľudia s PINom (predvolené: prístupy len cez PIN a používatelia v skupine alebo správcovia úsekov; ostatní pracujú podľa NetBoxu a plugin nevidia) alebo Všetci.

Núdza na serveri (všetci strážcovia a superuseri dostanú e-mail, zapíše sa do auditu):

python manage.py userpin_keeper --add <používateľ>
python manage.py userpin_default_deny --on|--off

Výnimky

Používateľ s výnimkou nie je viazaný ochranou: pracuje s oprávneniami, ktoré mu dáva NetBox. Jeho skupiny, prístupy a roly ostávajú a platia znova, keď sa výnimka odoberie alebo skončí. Výnimku nastavuje len strážca na stránke Chránené oblasti → Výnimky: používateľ, voliteľný koniec a dôvod. Ostatní strážcovia dostanú e-mail a zapíše sa do auditu. Superuser s výnimkou vidí všetko bez PINu.

Čo smie používateľ s výnimkou (od 2.0.1)

Výnimka už nie je „všetko alebo nič“. Strážca pri každej výnimke zaškrtáva, čo smie používateľ používať z účtových stránok a API:

Prečo to je dôležité. NetBox dáva každému prihlásenému právo na vlastné API tokeny (DEFAULT_PERMISSIONS). Používateľ bez akýchkoľvek práv preto vidí v menu Admin → API Tokens. Token pritom nesie len oprávnenia svojho majiteľa, no požiadavky s tokenom plugin PIN-om neposudzuje, takže používateľ s právami by cez token čítal aj mimo svojich úsekov. Zoznam povolení to rieši bez zásahu do konfigurácie NetBoxu.

Správcovia úsekov

  • Vymenúva ich strážca s úsekom (typy objektov oblasti; nič nezaškrtnuté = celá oblasť). Potrebuje PIN a 2FA, rolu oddelenia nepotrebuje.
  • Správca má plnú moc nad svojím úsekom: skupiny, polia, členov a žiadosti. Strážcovia sú nad ním.
  • Žiadosti o jeho typy idú jemu aj strážcom; rozhodnutie sa posiela e-mailom žiadateľovi, strážcom a správcovi.
  • Prístup len cez PIN vytvorený strážcom patrí strážcom. Správca vidí len tie, ktoré sú pod ním, a zakladá ich iba do skupín svojho úseku (strážcovia dostanú e-mail). Strážca môže prístup presunúť pod správcu.
  • Vytváranie oblasti, ciele, profily a pridávanie/odoberanie správcov patrí strážcom; správca celej oblasti si ponecháva práva nad oblasťou.
  • Núdza: python manage.py userpin_area_owners <kľúč-oblasti> --set meno1 meno2 (odmietne ľudí bez PINu a 2FA, superuserov a strážcov, ak nedáš --force).

Prístupy len cez PIN (PIN-only)

User PIN › Prístup len cez PIN › Ľudia len s PIN-om (strážcovia a správcovia úsekov). Zadaj meno, e-mail a skupinu (skupina je voliteľná). Vznikne technický používateľ bez použiteľného hesla.

Prihlásenie

  • Osoba dostane e-mailom osobný odkaz (platí 7 dní pre prvé nastavenie), zvolí si PIN (8+ znakov) a prihlási sa odkazom a PINom.
  • Odvtedy všetci používajú jednu spoločnú stránku (predvolene /pin/; strážca zvolí adresu na stránke PIN-only, napr. /tenanti/; bez ohľadu na veľkosť písmen; uloží sa ako záložka) a zadajú len PIN: PIN povie, kto to je, takže dvaja ľudia nikdy nemajú rovnaký PIN (druhý je vyzvaný zvoliť iný).
  • Zoznam adries (IP / siete) pre prístup obmedzí počítače.
  • E-maily ľuďom len s PIN-om idú na ich vlastnú adresu bez ohľadu na povolené domény.

Obmedzenia osoby

  • Bez hesla, 2FA, API a tokenu; nikdy strážca, správca ani výnimka. Účtové stránky a stránky pluginu sú jej zatvorené (iba Môj prístup, Zmeniť môj PIN, Odhlásiť).
  • Nie je používateľom NetBoxu: je skrytá vo všetkých zoznamoch používateľov, v rozbaľovacích zoznamoch aj v API. Záznam zmien v NetBoxe ukazuje technického používateľa (PinUser0001 …).
  • Bez skupiny môže len zmeniť svoj PIN. Rozbaľovacie zoznamy vo formulároch pre ňu fungujú (stručné zoznamy API), zvyšok API ostáva zatvorený. Ukladá si vlastné stĺpce tabuliek.

Zlé PINy (predvolené 5 na krok, čakanie 10, 20, 30 s; vlastné pravidlá na stránke PIN-only aj pre prístup)

  • Na osobnom odkaze sa osoba pozná: po každých 5 zlých PINoch čakanie, po poslednom kroku je prístup zablokovaný (osoba aj strážcovia dostanú e-mail; odblokuje len správca).
  • Na spoločnej stránke sa zlý PIN nedá pripísať osobe: čaká počítač (jeho adresa) podľa rovnakých krokov, posledné čakanie sa opakuje, nikto sa neblokuje a strážcovia dostanú e-mail po každom plnom kole (15).

Správa prístupu

  • Zakázať / povoliť: na stránke zastavenia je „zakázal X od …“ a tlačidlo „opýtať sa správcu“ (najviac raz za hodinu).
  • Platnosť prístupu sa dá meniť neskôr (e-maily 30 dní a 1 deň pred koncom), vynútená zmena PINu, vlastný jazyk pre stránky PIN aj pre NetBox, stabilné ID PinUser0001 s voľným aliasom a popisom.
  • Relácia: nečinnosť 30 min (5–240) a najviac 8 h (1–24), nastaviteľné pre každý prístup, voliteľný zoznam IP a voliteľný koniec.
  • „Zabudol som PIN“ pošle odkaz na nový (1 hodina, raz); neplatí pre zakázaný alebo skončený prístup.
  • Strážca môže poslať nový odkaz (starý prestane platiť), zmazať PIN, odvolať (ukončí všetky relácie), obnoviť a zmazať prístup.

E-maily oboma smermi

  • Osoba dostane e-mail o každej zmene, ktorú urobí správca (zakázanie, povolenie, reset PINu, platnosť, jazyky, pravidlá, pracovný čas). Vypínač E-mailovať osobe o zmenách prístupu je globálny a aj pre každý prístup.
  • Správcovia dostanú zhrnutie toho, čo osoba v NetBoxe zmenila, buď každých N minút (predvolene 60), alebo pri každej zmene (nikdy oboje naraz). Predmet: PinUser0001 vykonal zmenu; telo: čas, objekt a zmenené polia (z → na). Odosiela sa až po uložení cez netbox-rq, takže ukladanie ostáva rýchle. Vypínač E-mailovať správcom, čo osoba zmenila je globálny aj pre prístup.

Pracovný čas

Všeobecné pravidlá sú na stránke PIN-only: krajina (pre štátne sviatky), pracovné dni (predvolene Po–Pi) a hodiny (predvolene 06:00–16:00); zapnutie je Obmedziť pracovný čas prístupov len cez PIN (predvolene vypnuté). Každý prístup môže mať vlastné pravidlá (napr. technik z Maďarska s maďarskými sviatkami), všeobecné, alebo žiadne.

  • Štátne sviatky dodáva knižnica holidays (funguje offline, vyžaduje pip install holidays; bez nej sa kontrolujú len dni a hodiny). Zoznam krajín: SK, CZ, HU, AT, PL, DE, UA, HR, SI, RO, BG, RS, GB, IE, FR, ES, IT, NL, BE, CH, SE, NO, DK, FI, PT, GR, LT, LV, EE, US, CA.
  • Sviatky určuje knižnica podľa platných zákonov. Napríklad na Slovensku sú v roku 2026 voľné dni 1. 1., 6. 1., Veľký piatok, Veľkonočný pondelok, 1. 5., 5. 7., 29. 8., 1. 11. a 24., 25., 26. 12.; 8. 5., 1. 9., 15. 9. a 17. 11. sú pracovné dni. Vlastné voľné dni ani dovolenky plugin nemá.
  • Mimo pracovného času sa osoba môže prihlásiť a pozerať, ale nemôže nič ukladať ani upravovať (žiadne ukladanie, pridanie, úprava, mazanie, zápis cez API). Pracovný čas je vždy viditeľný (úvodná stránka aj horná lišta, v jazyku osoby).
  • Keď čas skončí počas práce, platí 30 minút a jedno uloženie, potom už len čítanie.

Rotácia kľúča

  1. Pridaj nový kľúč vedľa starého a nastav ho ako aktívny: 'encryption_keys': {'k1': '<starý>', 'k2': '<nový>'}, 'active_key_id': 'k2'.
  2. Reštartuj NetBox a spusti userpin_rotate_key.
  3. Over userpin_check. Index stránky PIN-only sa presunie na nový kľúč, až keď sa každá osoba prihlási znova: starý kľúč odstráň až keď to userpin_check povie (ukáže, koľko ešte čaká).

Plugin kľúč nikdy nevytvára ani neprepína sám: chýbajúci alebo zlý kľúč skončí chybou. Nový kľúč ulož bokom (správca hesiel) a pred výmenou urob zálohu databázy.

Kontrola: pin_check.sh

Skript tools/pin_check.sh kontroluje všetko, čo sa dá zvonku (a so --server aj na serveri). Nikdy neukladá ani nevypisuje PIN či token.

bash pin_check.sh http://172.30.1.25                       # iba anonymné kontroly
bash pin_check.sh http://172.30.1.25 --pin /pin/           # + prihlási osobu len s PIN-om (PIN sa pýta potichu)
NB_TOKEN=xxxx bash pin_check.sh http://172.30.1.25         # + kontroly s API tokenom
sudo bash pin_check.sh http://127.0.0.1 --pin /pin/ --server   # + migrácie, služby, kľúče, strážcovia

Voľby: --pin <cesta> (adresa stránky PIN-only), --wrong (skúsi jeden zlý PIN; počíta sa ako chybný pokus!), --write (skúsi pridať tenanta ako osoba len s PIN-om a zmaže ho), --server (vyžaduje root). Premenné: NB_TOKEN, NB_VENV, NB_DIR, LIST. Výsledok: počet OK / FAIL / WARN. Známe neškodné upozornenia: /static/docs/ servíruje nginx (dá sa zatvoriť location /static/docs/ { return 404; }) a LOGIN_REQUIRED nie je True (nastav v configuration.py).

Bezpečnostný model

PIN ──Argon2id + soľ──► hash ──AES-256-GCM (kľúč z konfigurácie, viazaný na ID používateľa)──► databáza
  • Samotný výpis databázy neobsahuje nič použiteľné, ani čo by sa dalo lámať offline.
  • Šifrovaný text je viazaný na používateľa: hash skopírovaný do riadku iného používateľa sa nedešifruje.
  • Zlé pokusy sa počítajú pod zámkom riadku, takže paralelné hádanie nezablokovanie neobíde.
  • Tajomstvá TOTP sú šifrované rovnako; kód TOTP sa prijme len raz.
  • Záložné kódy (100 bitov) a e-mailové kódy obnovy sa ukladajú len ako odtlačky, jednorazové a krátko platné.
  • Obnova nikdy neobíde 2FA. PIN je len autentifikačný faktor („som to naozaj ja pri tomto počítači“), nepoužíva sa ako kľúč na šifrovanie iných dát.
  • Požiadavky s API tokenom plugin PIN-om neposudzuje (token nesie oprávnenia NetBoxu): preto sú tokeny predvolene zakázané a pri výnimkách sa povoľujú po jednom.
  • Prístup na server riadi firewall; druhý port ani hostname pre PIN-only plugin nevynucuje, v prípade potreby sa rieši v nginxe a firewalle.

Zmeny

Verzia v kóde je 2.0.0 (vydanie na GitHube) a 2.0.1 (vetva feature/exception-allowlist). Pôvodný základ bol 0.38.4 (commit 7bed7de); priebežné čísla 2.0.1 až 2.2.2 v histórii commitov boli pracovné označenia, všetko je zahrnuté v aktuálnej línii 2.0.0 a nižšie je rozdelené podľa tém.

2.0.1 – oprávnenia výnimiek

  • Výnimka už nie je „všetko alebo nič“: strážca zaškrtáva, čo smie používateľ používať (heslo predvolene povolené; profil, predvoľby, záložky, notifikácie, odbery, API tokeny a API s tokenom na povolenie).
  • Čo nie je povolené, je skryté z menu a kariet a zakázané priamou adresou (403); token bez povoleného API je odmietnutý. Strážca je bez obmedzení.
  • Odkaz „Zmeniť heslo“ v menu používateľa; zvonček sa skryje, ak nie sú povolené notifikácie.
  • Šípka ▾ pod menom používateľa so zaškrtávacími poľami a zelenými/červenými štítkami; existujúci používateľ sa neponúka znova a opätovné pridanie nič neprepíše.
  • Nové pole PolicyException.allowed (migrácia 0042); slovenský preklad.

Kľúče a bezpečnosť

  • Rotácia kľúča pokrýva aj 2FA, záložné kódy, SMTP heslo a index PIN-only; príkaz userpin_check overí všetky šifrované hodnoty.
  • Odstránenie PINu používateľa bez 2FA; príkaz userpin_area_owners kontroluje oprávnenosť.
  • Master spravuje PINy, kým nie je zástupca CORE, aj pri existujúcich strážcoch.

Nový model ochrany

  • PIN riadi iba prístupy len cez PIN a používateľov v skupine alebo správcov; ostatní pracujú podľa oprávnení NetBoxu (menu a API kľúče vrátane).
  • Prístupy len cez PIN nie sú používatelia NetBoxu (skryté v zoznamoch), nemajú žiadosti a bez skupiny môžu len zmeniť PIN.
  • Ochrana ZAP riadi všetkých okrem strážcov a výnimiek; VYP necháva NetBox a pozastaví prístupy len cez PIN. Prepínač ZAP/VYP je v rozhraní (len strážcovia) a ukazuje skutočný stav. Výnimka vs. skupina: skupina čaká pod výnimkou.
  • Strážcovia ochrany: pravidlo posledného strážcu, núdzové príkazy (userpin_keeper, userpin_default_deny).

Správcovia úsekov a žiadosti

  • Správca úseku s plnou mocou nad svojím úsekom (strážcovia nad ním); prístupy len cez PIN pod správcom; žiadosti správcovi aj strážcom s e-mailami o rozhodnutiach.
  • Vymenúva len strážca; uvoľnená oprávnenosť (PIN + 2FA, bez roly oddelenia).

Prístupy len cez PIN

  • E-maily oboma smermi: osoba o zmenách správcu; správcovia zhrnutie každých N minút alebo pri každej zmene (nie oboje), predmet PinUserNNNN vykonal zmenu, telo: čas, objekt, zmenené polia (z → na); odosielanie po uložení cez netbox-rq.
  • Rozbaľovacie zoznamy vo formulároch fungujú; ukladanie vlastných stĺpcov tabuliek.
  • Podmienky pre polia typu relácia: obsahuje / začína na / je jedno z, viac hodnôt, tlačidlo Podmienky.

Pracovný čas (od 2.2)

  • Všeobecné a vlastné pravidlá, krajina so štátnymi sviatkami (knižnica holidays), pracovné dni a hodiny; vždy zobrazený pracovný čas.
  • Mimo času len čítanie; po konci 30 minút a jedno uloženie; krajina v jazyku osoby, dni Po–Pi.

Nástroje a príprava na upgrade

  • tools/pin_check.sh – kontrola zvonku aj na serveri; závislosť holidays v pyproject.toml.
  • Príprava local_requirements.txt pre upgrade NetBoxu v rámci 4.7.x.
  • Slovenské preklady, README s modelom 2.x, štítok verzie 2.0.0.

Čo plugin zatiaľ nerobí

  • Dovolenky a vlastné firemné voľné dni v pracovnom čase.
  • API pre bežných používateľov v skupine je stále riadené právami skupiny (nie je úplne uzavreté).
  • Vlastné prihlasovanie PIN-only na samostatnom porte/hostname (rieši sa v nginxe a firewalle).
