My PIN

Who: every user who may use a PIN. Every signed-in user sees the page My PIN.
When: at first use, when the validity expires (after 180 days by default), after a reset.
Depends on: the permission to use a PIN (below); 2FA and an e-mail in a verified domain for recovery of a forgotten PIN.

Who may use a PIN

It is decided by the setting Who may use a PIN (Settings → Access & PIN policy) and by the flag of each user (the Users page):

Default (new accounts)may notmay
  • A superuser always may.
  • Whoever holds a role in the PIN administration (CORE, head, delegate) or awaits the acceptance of an invitation always may: they need the PIN to accept and to work.
  • Whoever may not sees on the page My PIN: Permitted to use a PIN: No – ask an administrator.

Setting and changing the PIN

  • Digits only, exactly the length in the settings (PIN length, 6 by default, range 4 to 12). An old PIN of another length stays valid until changed.
  • Weak PINs are rejected (when Block weak PINs is on, the default): repeated digits and patterns (111111, 121212, 123123), runs up or down (123456, 654321) and the own list Additional blocked PINs (one per line or comma separated).
  • Nobody, not even an administrator, can read the PIN: an administrator can only reset it.
  • A PIN change or reset invalidates every existing unlock of the user (in all sessions).

Unlocking

A protected page asks for the PIN (Enter your PIN). After the correct PIN it is unlocked for Unlock duration minutes (15 by default; 1 to 1440). With Extend unlock on activity on (the default) every view of a protected page restarts the timer, so the unlock expires after inactivity. Unlock scope: one unlock for everything (default) or a separate one per scope (plugin / area). Require 2FA on every unlock (off by default) also requires a 2FA code; a user without 2FA is then not unlocked.

The unlock does not apply when the PIN is suspended, has expired, or the user may no longer use a PIN. The Test unlock page in the menu is protected by its own scope test and serves to try it out.

Wrong attempts and lockout

After Max failed attempts (5 by default; 1 to 50) the account is locked for Lockout duration minutes (30 by default; up to 7 days). Wrong PINs and wrong 2FA codes are counted separately: a correct PIN does not reset wrong 2FA codes and vice versa. Counting happens under a row lock, so parallel guessing cannot bypass the lockout. A locked user sees Too many failed attempts. Try again after …. An administrator (Clear lockout) or the passing of time unlocks.

Validity and rotation

A PIN is valid for PIN max age days (180 by default; 1 to 3650). Warn before expiry (14 days by default) sends an e-mail once and shows a notice. After the expiry, or when an administrator forces a change, the PIN must be changed before the next use (Change required). Periodic changes are a company policy; NIST SP 800-63B-4 does not recommend them: set it by your rules.

Forgotten PIN (self-service)

  1. My PIN → Forgot PIN (or the link Forgot your PIN? on the unlock page) → Send code. It is sent only to an address in a verified domain. An 8-digit code is sent; valid for Recovery code validity minutes, at most 5 attempts, a new code after 60 s at the earliest.
  2. Enter the e-mail code and a 2FA code (or a backup code) and the new PIN. On success the e-mail Your PIN was recovered arrives.

Recovery is not offered (the page lists the reasons) if: it is switched off, the user may not use a PIN, NetBox cannot send e-mails, the account has no e-mail, the e-mail is not in a verified domain, or 2FA is not set up. Then an administrator resets the PIN. Recovery never bypasses 2FA.

Two-factor authentication (2FA)

Who: every user sets it up themselves (My PIN → Set up 2FA).
When: as soon as possible: without 2FA administrative actions cannot be confirmed, a forgotten PIN cannot be recovered, and a role (head, delegate, CORE deputy) cannot be accepted.
Depends on: an authenticator app on the phone with TOTP (Microsoft / Google Authenticator etc.), the package segno (QR code).
  1. Set up 2FA → 1. Scan with your authenticator app the QR code (or enter the key manually: Can't scan? Enter this key manually).
  2. 2. Enter the 6-digit code from the app. The backup codes are shown at once (Save these codes now, buttons Copy and I have saved them).
  • A TOTP code is accepted only once (replay protection).
  • Disabling 2FA (My PIN → Disable 2FA) needs the PIN and a 2FA code. Without 2FA administrative actions cannot be confirmed and a PIN cannot be recovered by yourself. The e-mail Two-factor authentication disabled arrives.

Backup codes

One-time codes instead of the app (e.g. after losing the phone). My PIN → Show backup codes needs the PIN and either a 2FA code or (without the phone) a verification code from an e-mail (No phone at hand? Get a verification code by e-mail). The codes are shown only in the browser (used ones are marked used); Generate new codes invalidates all the old ones. The codes themselves are never e-mailed. After every viewing the user gets an e-mail and it is written to the audit log.

Lost phone

  1. Use a backup code.
  2. If you have none either: another administrator starts Reset 2FA (the user confirms it with the PIN and sets up the new phone).
  3. If nobody can do it (e.g. the master without the phone and codes): the server administrator runs python manage.py userpin_reset_2fa <user>. The 2FA is removed at once and it is written to the audit log. The command with the exact paths is shown by My PIN and Users → Emergency: server command.

Confirming administrative actions

An administrative action is confirmed in a dialog directly on the page (Confirm your identity): Your PIN and a 2FA code (6 digits from the app, or a backup code). The confirmation is valid for Administrative window minutes (5 by default; 1 to 60) and the action continues without leaving the page. Actions are of two levels:

LevelWhat it needsExamples
PIN only (default)the PIN; with Require 2FA also for settings on, 2FA as wellsaving Settings and Mail, allow/deny a PIN, clear a lockout, force a change, moves between departments
PIN + 2FAalways 2FA as wellresets, suspension, roles, dissolving a department

If you switch off Require PIN + 2FA for administrative actions, the PIN alone is enough. The administration of protected areas is confirmed differently: the PIN is unlocked once and 2FA is asked only every 2FA asked again after hours (8 by default; 1 to 168), not at every change.
