E-mails: how the plugin sends mail

Who sets it up: the master and CORE deputies with the permission to edit settings (the Mail page). The NetBox server (EMAIL in configuration.py) is set up by the server administrator.
When: right after the installation. Without mail set up the plugin sends no e-mails: recovery of a forgotten PIN, invitations to roles and notifications do not work.
Depends on: a sender + an SMTP server, a verified domain of the recipient, an address in the recipient's account.

When an e-mail is really sent

An e-mail to a user goes out only when all four conditions are met:

  1. mail is set up (see below),
  2. the user has an e-mail address in the account,
  3. the domain of that address is among the verified domains (the Domains chapter),
  4. for security notifications: the switch Security notifications by e-mail is on.

If any of them is missing the e-mail is silently not sent and the action is carried out. The e-mail state of a user is seen on the Users page in the E-mail column: no e-mail (the address is missing), domain (the address is outside the verified domains). Otherwise the address itself is shown. When sending fails (e.g. the server is unreachable) an E-mail failed event with the error is written to the audit log; the action that triggered the e-mail is not spoiled.

Users never enter any mail credentials: one service account is used.

What an e-mail looks like

  • Plain text (no HTML). The subject has the prefix [NetBox PIN] (e.g. [NetBox PIN] Your PIN was changed).
  • At the end there is the footer NetBox User PIN. This is an automatic message.
  • The text is in the language from Settings → Language (for PIN-only people in the language set for their access).
  • Sender: Sender name + the address (the default name is NetBox PIN).

The Mail page

Who sees it: CORE (master and deputies). Nobody else has the page. Exception: when there are protection keepers and active CORE deputies, a superuser who is not a CORE deputy does not see it.
Who can change it: the master and a CORE deputy with the permission Can edit settings (switched on by the master on the CORE (deputies) page). Others see the page marked Read-only view.
Confirmation: saving needs the PIN (and 2FA when Require 2FA also for settings is on). The connection test and the test e-mail need no confirmation.
Four eyes: when approval is on and the option "… for settings and mail settings" (on by default) is on, saving the mail settings and adding a domain create a request for a second person.

Status and the connection test

The Status card shows Used: SMTP from this page, NetBox configuration or not configured, and accordingly the server, the account (or no authentication) and the sender. The Test connection button connects to the SMTP server from the page (and logs in) and writes the result. It works only for the SMTP from the Mail page, not for the NetBox configuration.

The test e-mail

Choose a recipient and press Send test e-mail. Only users who may use a PIN and have an e-mail in a verified domain can be chosen; the picker shows the account, the name and the address. If nobody qualifies, the page says so. Result: Test e-mail sent to … or an error pointing to the audit log.

Allowed e-mail domains

Who: whoever may change the mail settings (see above).
When: once for each domain that is to receive e-mails. Add a new one also when a company with another domain joins.
Depends on: mail must be set up and somebody with an address in that domain must be able to read the code.

Mail goes only to addresses in verified domains. Until a domain is verified, e-mails to it are not sent (the list says not verified – no e-mails yet; with no domains it says No domain – no e-mails are sent).

  • A domain is written e.g. @company.com (the at sign may also be left out; the plugin strips it and converts to lower case). It must contain a dot and no spaces.
  • The match is exact: company.com lets jan@company.com through, but not sub-domains (jan@mail.company.com) or look-alikes (company.com.evil.com).

Adding and verifying a domain

  1. In the card Allowed e-mail domains write the domain and press Add. The dialog Verify domain opens at once. (With four-eyes approval on, the addition must be approved first.)
  2. 1. Address in this domain: write one address that ends with this domain and press Send code. An e-mail with an 8-digit code is sent.
  3. 2. Code from the e-mail: enter the code and press Verify.

The code is valid for Recovery code validity minutes (15 by default) and can be entered at most 5 times (then a new one must be sent). If you already have a code, the dialog has the link Already have a code? Enter it directly. On success the plugin stores who verified the domain and through which address. Errors: The address must end with @domain, No mail server is configured, The code is wrong or expired.

  • Verify again is available at any time (e.g. for a new address); it does not cancel the domain.
  • Removing (the button at the domain, with a confirmation) cancels the domain at once: e-mails to it stop. Removing does not need four-eyes approval.
  • Adding, verifying and removing are written to the audit log.
