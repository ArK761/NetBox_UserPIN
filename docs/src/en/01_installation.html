What the plugin needs and what it adds to NetBox

Who: the server administrator (command line and configuration.py access).
When: before the first installation; at every plugin or NetBox update.
Depends on: NetBox 4.7.0 or newer, Python 3.12+, a running netbox-rq worker, internet access (GitHub, PyPI) during installation.

Requirements

WhatDetails
NetBoxversion 4.7.0 or newer (the plugin has min_version = 4.7.0 and no upper limit). With an older NetBox the plugin does not load.
Python3.12 or newer (requires-python >= 3.12).
netbox-rq workerThe plugin registers a system job User PIN role housekeeping that runs every 5 minutes. It expires invitations, moves and exceptions, sends reminders, returns rights after a temporary hand-over, announces the end of PIN-only accesses and sends the summaries of changes. The e-mails about the changes of a PIN-only person also go through the default queue. When the worker does not run, these things are not done.
Databasethe tables of the plugin are created by migrate (migrations 0001 to 0044).

Mind it: installing with --no-deps does not install the dependencies. On a server where the plugin has never been, install them separately (see the Installation chapter).

What the plugin adds to NetBox

  • The menu "User PIN" with the items: My PIN, My roles, My access, Test unlock, People with a PIN only, Users, Departments, Protected areas, Approvals (four eyes), Audit log, Settings, Mail, CORE (deputies). Which item a user sees depends on the role (see the Roles chapter).
  • The address of the plugin: /plugins/user-pin/.
  • Two middleware classes that are added automatically: PluginLanguageMiddleware (language of the plugin pages) and AreaGuardMiddleware (the guard of the protected areas and of the global protection). They are not written into configuration.py.
  • Three event types in the NetBox notifications (the bell): PIN four-eyes approval requested, PIN area access requested, PIN role / department change.
  • NetBox permissions named User PIN: … (deputies, settings editors, departments). The plugin creates and manages them itself: do not edit them by hand.

Installation

Who: the server administrator (root or sudo).
When: once, on every NetBox server separately (test, production).
Depends on: the chapter What the plugin needs; a generated key (next chapter).

1. Packages

source /opt/netbox/venv/bin/activate
pip install "argon2-cffi>=23.1" "cryptography>=42" "segno>=1.5" "holidays>=0.50"
pip install --upgrade --force-reinstall --no-deps "git+https://github.com/ArK761/NetBox_UserPIN.git@2.0.0"

Instead of @2.0.0 you can use any tag or commit. After the installation pip may print a warning about python-dateutil (see Troubleshooting): it is harmless.

2. The encryption key

Generate it and store it aside before you switch the plugin on. The procedure is in the chapter Encryption key.

3. Configuration

In /opt/netbox/netbox/netbox/configuration.py add 'netbox_user_pin' to PLUGINS and a block to PLUGINS_CONFIG:

PLUGINS = [
    # ... your other plugins ...
    'netbox_user_pin',
]

PLUGINS_CONFIG = {
    # ... the settings of the other plugins ...
    'netbox_user_pin': {
        'encryption_keys': {'k1': '<your key>'},
        'active_key_id': 'k1',
    },
}
Mind the two blocks. If you already have other plugins in PLUGINS and PLUGINS_CONFIG, the line and the block are added, not replaced. Check the commas and apostrophes as well: an error in the file stops the whole NetBox.

4. Migrations and restart

cd /opt/netbox/netbox
python manage.py migrate netbox_user_pin
sudo systemctl restart netbox netbox-rq

migrate netbox_user_pin creates the tables of the plugin. If it reports No installed app with label 'netbox_user_pin', the plugin is not in the PLUGINS list.

5. Check that everything runs

python manage.py showmigrations netbox_user_pin | tail -3      # every line has [X]
python manage.py userpin_check                                  # after a fresh install: OK: 0 ... failed: 0
systemctl is-active netbox netbox-rq                            # active, active

User PIN appears in the NetBox menu. In Settings there is the card Encryption key with the active key and its fingerprint.

6. First steps in the interface

  1. Sign in as superuser → User PIN → My PIN → Set PIN and Set up 2FA (administrative actions need 2FA).
  2. On the Mail page set up sending and verify at least one domain (see the E-mails chapter).
  3. On the Users page allow those who are to use a PIN.

What happens when the configuration is wrong

At start the plugin checks the keys and NetBox does not start if there is a problem (a key is never generated or switched silently). So always watch journalctl -u netbox -n 50 after editing configuration.py.

Start-up errorCause
encryption_keys must be a non-empty dictencryption_keys is missing or empty
invalid key id '…'the key id is empty or contains a colon (:)
must be a base64 32 byte key or a secret of at least 32 charactersthe key is shorter than 32 characters and is not a valid base64 key
several encryption keys are configured; set 'active_key_id'there are several keys and active_key_id is missing
active_key_id '…' is not in encryption_keysthe active id is not among the keys

Updating the plugin and NetBox

Who: the server administrator.
When: at a new version of the plugin or NetBox.
Depends on: a database backup (before a migration), the pinned version in local_requirements.txt.

Updating just the plugin (one line)

sudo bash -c 'source /opt/netbox/venv/bin/activate && pip install --upgrade holidays && pip install --upgrade --force-reinstall --no-deps "git+https://github.com/ArK761/NetBox_UserPIN.git@<tag-or-commit>" && cd /opt/netbox/netbox && python manage.py migrate netbox_user_pin && systemctl restart netbox netbox-rq'
Production: back up the database before the migration, for example sudo -u postgres pg_dump netbox | gzip > /root/netbox-$(date +%F-%H%M).sql.gz. Do not touch the keys in configuration.py meanwhile.

Upgrading NetBox itself

upgrade.sh creates the virtual environment anew and installs only what is in requirements.txt and local_requirements.txt. A plugin that is not listed there disappears after the upgrade. Lines in /opt/netbox/local_requirements.txt:

netbox-librenms-plugin
netbox-qrcode
git+https://github.com/ArK761/NetBox_UserPIN.git@2.0.0
  • A package from PyPI needs only its name. A plugin from GitHub needs the whole link.
  • A line without @… installs the latest commit of the main branch (not the latest release; pip does not know GitHub Releases, only branches, tags and commits). If the code of a plugin is on another branch, keep the pinned commit.
  • After the upgrade check the plugin versions (the badge User PIN vX · commit) and run userpin_check.
