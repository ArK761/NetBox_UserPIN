Users (the PIN page)

Who sees it: CORE (master and deputies) everybody; heads and delegates only their department. An ordinary user does not have the page.
When: in PIN administration: allowing, resets, suspension, clearing lockouts.
Depends on: the administrator's role (the Roles chapter); a PIN or PIN + 2FA confirmation before the first action.

Menu User PIN → Users, heading User PINs.

Filters

  • Search (name, e-mail).
  • Status: All users / PIN active / No PIN yet / No 2FA / E-mail issue (missing / domain) / Locked out / Suspended / Not permitted.
  • Department: all / without a department / a given one. Role: all / master / head / delegate / invited / without a role.
  • View: List or By departments (a tree: head → delegates → members; department colours: green = a head and at least 2 delegates, yellow = delegates missing, red blinking = no head).

Actions for a user

ActionConfirmationWhat it does
Allow / Deny / DefaultPINsets the flag of the user (see the table in the My PIN chapter). With four-eyes approval on for the category "allowing PIN use" it creates a request
Reset PINPIN + 2FAstarts a reset; the user confirms it in their own session with a 2FA code and sets a new PIN. Valid for Administrator reset valid hours (24 by default). The old PIN works until the user confirms
Reset 2FAPIN + 2FAstarts a reset; the user confirms it with the PIN and sets up 2FA on a new phone
Cancel resetPIN + 2FAcancels a pending reset
Suspend / Lift suspensionPIN + 2FAblocks the PIN at once (suspected leak, absence), alone, without a second person; the user gets an e-mail
Clear lockoutPINclears the lockout after wrong attempts
Force changePINthe user must change the PIN at the next use
Remove PINPIN + 2FAonly for a user without 2FA who cannot confirm a reset: the PIN is removed and the user sets a new one at the next prompt. With 2FA a reset must be started
A reset never reveals the new PIN to the administrator. The administrator starts the reset, the user finishes it.

Who may manage whom

AdministratorWhom they may manage
Master (superuser)everybody except themselves
CORE deputyeverybody except the master, other CORE deputies and themselves
Department headthe members of their department except themselves and other heads
Department delegatethe members of their department who have no role

Nobody manages themselves (you change your own PIN in My PIN). On a forbidden action the page answers: Delegates cannot manage the master, other delegates or themselves.

Emergency 2FA reset

In the Actions menu at a user there is Emergency: server command (2FA): a ready-made userpin_reset_2fa command to run as root. Use it only when the normal way (a reset confirmed by the user with the PIN) is not possible. The 2FA is removed at once and the event is written to the audit log.
