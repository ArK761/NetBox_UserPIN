The encryption key

Who: exclusively the server administrator (the key is only in configuration.py). Nobody in the interface sees it; Settings shows only its name and fingerprint.
When: you generate it before the first installation. You replace it on a suspected leak or by the company policy.
Depends on: everything the plugin encrypts cannot be read without the key. So the key must be backed up separately from the database.

What the key protects

Under the key are stored (AES-256-GCM encryption, bound to the particular user):

  • the PIN hash of every user (the PIN is first hashed with Argon2id and a salt and only the hash is encrypted),
  • the 2FA (TOTP) secret of every user,
  • the 2FA backup codes,
  • the SMTP password from the Mail page.

The key is also used to compute digests (these are not encrypted): the lookup index of the PIN of the PIN-only people and the verification codes of the domains. A database dump alone therefore contains nothing usable, not even something to brute-force offline.

How to generate a key

# while the plugin does not run yet – plain Python:
python3 -c "import base64,os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"

# or any long random text:
openssl rand -base64 64 | tr -d '\n'

# once the plugin runs:
cd /opt/netbox/netbox && python manage.py userpin_generate_key --key-id k1

userpin_generate_key only prints the key, it stores it nowhere. --key-id is only the name it gets in the configuration (k1 by default).

Which key the plugin accepts

Form of the keyWhat happens
a base64 (urlsafe) string that is exactly 32 bytesused directly
any other string with at least 32 charactersa 32-byte key is derived from it (HKDF-SHA256)
a shorter stringNetBox does not start (an error at start)

A longer key is not stronger: the encryption always uses 256 bits. What matters is that it is random (not an invented password). The key name (k1) must not be empty or contain a colon.

Writing it into the configuration

PLUGINS_CONFIG = {
    'netbox_user_pin': {
        'encryption_keys': {'k1': '<key>'},
        'active_key_id': 'k1',      # may be left out with a single key
    },
}

Backing up the key

  • Store the key offline (a password manager, a safe) and never in the same backup as the database. Whoever has both can decrypt.
  • When the key is lost, the NetBox data stays intact, but everything the plugin stored under the key is irretrievably gone: PINs, 2FA, backup codes, the SMTP password and the sign-in of the PIN-only people. Everybody has to set them up again.
  • Check that the backup matches: in User PIN → Settings there is the card Encryption key with Active key, Fingerprint and Configured keys. Compare the fingerprint with the note at the offline backup.

Replacing the key (rotation)

During a rotation every encrypted value is re-encrypted with the new key. The old key stays in the configuration until everything has moved.

  1. Back up the database (to be safe).
  2. Generate a new key and store it aside.
  3. In configuration.py add the new key next to the old one and make it active: 
    'encryption_keys': {'k1': '<old>', 'k2': '<new>'},
'active_key_id': 'k2',
  4. Restart NetBox: sudo systemctl restart netbox netbox-rq.
  5. Re-encrypt: python manage.py userpin_rotate_key. It runs in one transaction: if even one value cannot be decrypted, nothing changes and the command prints what failed. On success it writes a key-rotation event to the audit log.
  6. Verify: python manage.py userpin_check.
  7. Remove the old key only when userpin_check prints Everything decrypts with the active key; old keys can be removed.

Why not delete the old key at once: the index of the PIN-only people moves to the new key only at each person's next sign-in. Until a person signs in, they wait for the old key. The command prints it (PIN-only accesses still on an old key: N) and then Do NOT remove the old key yet.

What userpin_check prints

LineMeaning
Active key: k2 fingerprint …the active key and its fingerprint
OK: N, encrypted with a non-active key: M, failed: F, PIN-only accesses still on an old key: GN values decrypted; M still use an old key; F cannot be decrypted; G PIN-only people wait for a sign-in
an error (the command ends with an error)at least one value cannot be decrypted: a wrong or missing key. Do not change k1 and send the output
The plugin never creates or switches a key by itself. A missing or wrong key ends with an error, not with a silent change.
